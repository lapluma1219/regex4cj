# 捕获组游标与大小提示验证

本批在Cangjie1.1.3、Apple Silicon macOS上构建成功，并通过36项原生测试、2414项接口契约对照、513次字符串起点差分和170条主要库固有方法映射检查。

## 新增行为

| 类型 | 新方法 | 行为 |
|---|---|---|
| GroupIter / BytesGroupIter | len | 返回剩余捕获槽位数，包括未参与的组 |
| GroupIter / BytesGroupIter | sizeHint | 返回剩余槽位数作为精确上下界 |
| GroupIter / BytesGroupIter | clone | 在当前进度复制独立游标；结果存储共享 |
| SetMatchesIter | sizeHint | 返回尚未扫描的规则槽位数作为两端提示，保留原仓库固定版本行为 |

例如`(a)(b)?`匹配`a`后共有3个槽位：整个匹配、组1和缺席的组2。读完前两个后len仍为1；下一次返回“组未参与”，再下一次才是“迭代结束”。复制游标不会把它倒回开头，推进副本也不会消耗原游标。

集合大小提示的语义不同：4条规则只有第2条命中时，初始提示仍是`(4, Some(4))`，取出编号1后为`(2, Some(2))`。固定原仓库直接返回底层未扫描布尔槽位数，包括未命中的槽位。因此该值甚至不能作为剩余命中数下界；这里记录兼容事实，不把它宣传为命中数量查询。依据为原仓库regex-automata/src/util/search.rs的PatternSetIter::size_hint及regex/src/regexset/string.rs的转发实现。

## 验证内容

- 新增54条捕获组操作轨迹：字符串和bytes，多个复制位置，原游标/副本不同推进速度，空匹配、缺席组、中文字节偏移、非法UTF-8及耗尽后复制。
- 原有128条集合迭代轨迹中的96条正向/反向/交错轨迹增加逐步sizeHint对照。
- 原生测试补充2项，直接检查独立游标、准确剩余数、耗尽状态、空集合与集合槽位提示。
- Rust探针与仓颉探针独立调用实际接口，比较每一步的数量、提示和捕获区间；不是单纯比较最终收集的数组。

[机器记录](group-cursor-2026-10-04.json)保存执行命令、结果、测试输出、工作区状态和118份源码哈希。[仓颉探针](../../cli/src/group_cursor_audit.cj)、[Rust探针](../../oracle/src/api_audit.rs)、[原生测试](../../examples/consumer/src/group_cursor_test.cj)可直接复核。

本批未重跑40阶段全套：新增方法只读取已有结果或复制游标，未修改匹配算法与原有next行为，采用针对新增状态契约的专项回归。此前[完整验收](append-builder-2026-10-04.md)只证明它所绑定的上一批源码，不冒充本批新记录。

## 仍存在的边界

这是显式方法适配，不是Rust trait本身。bytes游标复制不保证捕获载荷数组深复制；搜索/分割迭代器的复制、Debug等仍待处理。全仓库50%的目标尚无可信分母，本批不作完成率声明。主要库现有170条固有方法映射不因新增trait适配而扩充分母；仓颉公开调用入口现在为190个，详见[接口清单](../api-catalog.md)。
