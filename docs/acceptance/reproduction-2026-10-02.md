## 本次验证的限制

第一次尝试使用空的 Cargo 下载缓存时，GitHub TLS 连接失败，命令行 Git 也返回 SSL_ERROR_SYSCALL。随后主动终止等待中的 Cargo 下载，失败报告记录 rust-build 退出码 -15；这不是引擎或测试失败。

成功的完整验收复用了已有 Cargo 依赖下载缓存，设置 `CARGO_NET_OFFLINE=true`，但仍在新的目标目录从源码编译 Rust 参照。没有复制旧二进制或使用外部上游考题。

因此，本次证明了源码、测试数据和已获取依赖能够在干净检出与新构建目录中完整复现；没有证明本机当前网络能完成首次依赖下载，也没有在新操作系统上验证。首次使用者仍需要能访问 GitHub 和 Cargo 依赖源。不要将这份记录描述为“完全离线首次构建”或“全新电脑验收”。

## 如何再次执行

依照 [上手指南](../getting-started.md) 配置工具链，从待交付提交创建新克隆，指定新的缓存目录。网络允许时再使用空的 CARGO_HOME 验证首次下载；已有依赖缓存时也可以正常验收，但应注明缓存条件。

以 Git 仓库为交付物，不依赖 dist 下的历史压缩包。后续代码改变后，应重新执行验收，不能沿用这份记录声称新提交已通过。
