## 重点边界检查

- `Ast.walkUntil`、`Hir.walkUntil`：进入或离开回调返回 `false` 都必须立即停止，不能继续访问后续节点。
- `ThompsonNfa`、`BoundedBacktracker`：捕获模式只接受 `0/1/2`，未知值必须报错。
- 缓存与迭代器：查找失败后清空旧捕获；复制迭代器后，推进原对象不能推进副本。
- 覆盖率统计器：多个运行记录按代码行合并，不重复计算；无有效库数据时必须失败；消费者和 CLI 的代码不混入库的分母。

## 如何理解“覆盖”

1. **案例通过**：该输入的输出满足断言；具名对照案例同时满足人工预期和固定 Rust 版本结果。
2. **公开入口执行过**：实测运行进入过该函数/构造方法，包含重载。它只说明执行到过，不能证明该入口所有特性正确。
3. **代码行覆盖**：编译器报告的可执行行中，至少执行一次的比例。不是整个源文件行数比例，也不是原仓库功能完成度。

当前尚有 788 行可执行代码未被此次运行覆盖，逐行位置已记录在 `validation/code-coverage.json` 的 `files[].missed_lines` 中，涉及语法结构、部分属性选择和引擎内部条件分支。

不将这些数字混成一个“完整度”。未穷举任意长文本、全部规则和配置组合；极端资源压力、跨平台行为及所有错误分支也不能由本次验收保证。`cjcov` 的分支信息属于实验能力，本报告不据此宣称分支全覆盖。原仓库尚未实现的能力不因现有测试通过而变成已支持。
