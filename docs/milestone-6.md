# 第六步：内联标志 m、s、U 与分组作用域

本阶段新增三个标志及启用、禁用、局部作用域语法。未增加 Unicode 属性表或大小写折叠，不把部分标志支持视作完整 Builder/flags 移植。

| 标志 | 启用后的行为 | 示例 |
|---|---|---|
| `m` | `^` 在文本开头或 LF 后匹配，`$` 在文本结尾或 LF 前匹配 | `(?m)^a$` |
| `s` | 点号也能匹配 LF | `(?s)a.b` |
| `U` | 交换量词的默认贪婪行为，追加 `?` 则再次交换 | `(?U)a+` 最短，`(?U)a+?` 最长 |

支持 `(?msU)`、`(?-s)`、`(?m-sU)` 等当前分组剩余部分的指令，及 `(?ms:expr)`、`(?-U:expr)` 等局部分组。局部分组不分配捕获编号。

## 作用域与边界

标志按模式文本顺序生效，并影响当前分组内后续的分支。进入普通、命名或非捕获分组时保存外层状态，离开后恢复。因此 `((?s).).` 的第一个点能匹配 LF，第二个点不能；`a(?s)|.` 中后面的点受 `s` 影响。

`\A` 和 `\z` 始终表示整段文本开头／结尾，不受 `m` 影响。这里的多行分隔符仅为 LF（U+000A）。例如 `(?m)^a$` 在 `a\r\n` 中不匹配该行的 `a`，因为 `$` 所在位置后面是 CR，不是 LF。CRLF 专用标志 `R` 尚未实现。

`U` 作用于 `*`、`+`、`?`、计数重复和相应的尾随 `?`；分组关闭后的量词使用恢复后的外层标志。`s` 不改变字符类行为，`m` 不改变匹配结果的 UTF-8 字节区间。

重复标志、重复或悬空的 `-`、缺失闭合符号及直接重复裸指令（如 `(?s)*`）明确报错。`i`、`x`、`R`、`u` 及其关闭形式当前都明确拒绝，避免看似接受但语义不一致。

## 实现与上游来源

固定上游 commit 仍为 `72d650cb0a880a01ab6dc2137c0888e8f89740f7`：

- `regex-syntax/src/ast/parse.rs` 的 `parse_flags` / `parse_flag`：标志语法、重复与否定规则，及不允许对裸标志指令使用量词的规则。
- `regex-syntax/src/hir/translate.rs`：词法作用域、`SwapGreed`、点号及锚点的标志解释。
- `regex-automata/src/util/look.rs` 的 `is_start_lf` / `is_end_lf`：LF 行首／行尾断言。

仓颉解析器把作用范围解析为每个表达式节点的属性，再编译到 NFA 状态：点号记录是否包含 LF，锚点记录是否识别行边界，量词记录最终分支优先级。匹配时不维护可变的全局标志；不同分组的设置不会相互覆盖。

本次 NFA 闭包可读取完整输入的相邻标量，所以从后续位置继续查找时仍按原文判断行边界，不把每次搜索的起点当作新的一行。

## 操作与验收

在 bash 中从仓库根目录执行：

```sh
source scripts/env.sh
cli/target/release/bin/main find '(?m)^[A-Z]+$' $'AB\nCD\n'
cli/target/release/bin/main find '(?U)a+' 'aaa'
cli/target/release/bin/main find '(?U)a+?' 'aaa'
```

第一条得到 `AB [0,2)` 和 `CD [3,5)`；第二条返回三个 `a`，第三条返回一个 `aaa`。`scripts/demo.sh` 同时展示两端的结果。

`tests/verify_flags.py` 增加 960 条差分用例（固定和确定性随机）、12 项接口对照、4 条黄金结果、14 个非法模式和 6 个当前未支持标志的拒绝检查。覆盖 LF/CRLF/CR、Unicode、嵌套恢复、分支传播、捕获、计数重复、替换、分割及绝对锚点。消费包新增两项原生测试，包含 NUL 与标志的组合。

统一验收入口仍是 `bash scripts/verify.sh`。本阶段目标总计 4,683 条差分用例、12 项仓颉原生测试、2 项 Rust 原生测试，另有各阶段接口／黄金／非法输入检查。测试通过只覆盖记录的范围，不代表完整上游等价。

下一步推进更多转义与字符类语法，随后补齐 Unicode 数据、大小写折叠、词边界、其余标志和 Builder。bytes、RegexSet、惰性迭代及优化引擎仍未完成。
