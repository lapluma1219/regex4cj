# 第二步：字符类、集合运算与计数重复

这是第二步的历史记录。第三步已加入捕获，并通过零宽重复正规化简化了下文的空表达式工作量示例；当前范围见 milestone-3.md。

在第一步的有序 Thompson NFA 上扩展，不依赖 Rust 或 std.regex 执行匹配。

## 新增行为

| 功能 | 示例 | 说明 |
|---|---|---|
| 字符列表、范围与并集 | `[abc]`、`[A-Z0-9_]` | 区间自动排序，合并重叠或相邻部分 |
| 取反 | `[^0-9]` | 对全部 Unicode 标量取补集，包括换行，不含 surrogate |
| Unicode 范围 | `[中-文]`、`[🙂-🙃]` | 按码点范围比较，输出仍是 UTF-8 字节偏移 |
| 嵌套类 | `[[a-c][x-z]]` | 支持嵌套字符集合 |
| 交集、差集、对称差 | `[a-z&&[^aeiou]]`、`[a-z--[a-f]]`、`[a-f~~d-z]` | 集合运算左结合，隐式并集优先 |
| 类内特殊字面量 | `[-a]`、`[a-]`、`[]a]`、`[\[\]\\]` | 保留前置／末尾横线、首位右括号和转义规则 |
| 精确次数 | `a{2}` | 恰好两次 |
| 有界次数 | `a{2,5}`、`a{2,5}?` | 保留贪婪／非贪婪优先级 |
| 无上界次数 | `a{2,}`、`a{2,}?` | 至少两次，随后通过 NFA 循环执行 |
| 零次及可空子表达式 | `a{0}`、`(a?){2,4}` | 不将空匹配与不匹配混淆 |

初始演示规则已经可以直接执行：

```sh
source scripts/env.sh
port/target/release/bin/main find '[A-Z]{2}-[0-9]{3}' 'order=AB-123; order=CD-456'
```

输出为起点、终点、文本：

```text
6   12  AB-123
20  26  CD-456
```

## 上游对应

所有依据仍固定在 `rust-lang/regex` 的 `72d650cb0a880a01ab6dc2137c0888e8f89740f7`。

- `regex-syntax/src/ast/parse.rs`：`parse_set_class`、`parse_set_class_open`、`parse_set_class_range`、`push_class_op`、`parse_counted_repetition`。
- `regex-syntax/src/hir/interval.rs` / `hir/mod.rs`：`IntervalSet` / `ClassUnicode` 的规范化区间表示及集合语义。
- `regex-automata/src/nfa/thompson/compiler.rs`：`c_exactly`、`c_bounded`、`c_at_least`。

`charset.cj` 是适应仓颉数据结构的区间集合实现，未复制上游全部泛型原地操作与大小写折叠逻辑。NFA 仍以 Rune 消耗输入，没有移植上游字符类的 UTF-8 字节自动机压缩。字符类通过二分查找判断成员。

有限重复的可选分支直接跳到最终后继，避免进入所有剩余的可选分支。无界重复复用第一步的循环及可空表达式优先级规则。

## 新增资源限制

- 每个重复次数最大 10000，十进制解析逐位检查，避免整数溢出。
- 编译递归调用累计最多 65536 次，包括最终不产生状态的空子表达式。
- NFA 仍最多 16384 状态；分组和字符类共享 64 层嵌套上限；模式仍最多 4096 UTF-8 字节。

仅有状态数量限制是不够的：例如 `((?:){10000}){10000}` 几乎不生成状态，但朴素展开会产生大量工作。新增工作量限制可对这种模式及时报错。这些上限是原型策略，不声称与 Rust 默认资源限制完全相同。

## 尚未支持

Unicode 属性及 `\d` / `\w` / `\s`、POSIX 命名字符类、十六进制转义、计数括号内空白（Rust 支持其中一些写法）、直接堆叠量词、捕获结果、标志、替换、分割、bytes、RegexSet 和优化引擎仍未完成。

仍有 `findAll` 立即收集、标量缓冲 O(n) 空间、错误位置和异常类型未对齐 Rust 等限制。当前字符类成员查询为 O(log r)，r 为规范化区间数；不要将 NFA 状态数直接视为完整模式大小来声称没有额外查询成本。

## 验证

新增测试 `tests/verify_classes.py` 覆盖范围端点、补集、集合优先级、随机集合与重复组合、Unicode 编码边界、计数零值、非法语法、资源限制和长输入。

新增 879 条差分、5 条独立黄金结果、10 项 find/isMatch 对照、16 个非法模式、5 个未支持模式和 4 项资源限制检查。全套结果由 `scripts/verify.sh` 写入仓库外的 `verification.json`。旧匹配测试中字符类和计数重复已从“应拒绝”列表移出。
