# 功能范围台账

`ledger.json`沿用100分功能规划权重，定义见[唯一交付计划](../delivery-plan.md)。这是范围管理，不是官方评分或已测得的完成百分比。

大项只有整体契约闭环才可标记“验收通过”。有限样例通过不意味着字面量工具、反向NFA或有界回溯整个公共模块已经完成；这些项目前标记“有差异”。

已经写明的叶子可以单独验收。叶子权重从原大项里扣出，合计仍是 100。`scripts/check_coverage.py` 打印的已验收权重只加总状态为“验收通过”的项。这个数字不是原仓库完成百分比。当前已验收叶子是 A5a（1，大小和嵌套上限）、C4a（2，捕获元数据与 SetMatches 双向迭代）、E1（1，`find match pikevm` 的区间文本和退出码）、D4a（1，有界回溯的非重叠迭代）。

`scripts/check_coverage.py`检查编号、权重和证据路径。测试文件存在只是引用完整，不是已执行通过的证据；实际运行状态见`docs/validation/latest.json`。下一阶段要拆出可逐条验收的行为项，再进行可信的加权汇总。不能把“解释了不兼容”算作“已经等价实现”。
