# 向原仓库完整行为对齐的工作路线

2026-10-04赛事规则核对更新：三方库须适配STS Cangjie1.1.3。本文原有“保持1.0.5”的安排只保留为历史验证基线，后续以1.1.3适配与赛事必交材料优先，详见[赛事要求对照](competition-requirements.md)。原仓库提交与Unicode版本仍固定。

用户在2026-10-03将目标从“主要使用功能可交付”扩大到“对齐原仓库所有行为”。此路线替代现状文档中暂停扩展功能的旧安排，不代表下面的内容已经实现。

## 范围与判断标准

参照仍固定为原仓库提交72d650cb0a880a01ab6dc2137c0888e8f89740f7，不同时追逐新版本。仓颉编译器已适配1.1.3，Unicode16和原仓库参照版本保持不变。

“所有行为”需要拆成三层分别记录：

1. 可观察功能：接受/拒绝哪些规则、返回哪些匹配与捕获、顺序、起点、空匹配、错误类别和内容。以原库执行结果作为参照。
2. 接口与状态：构造、迭代、复制、双向访问、结果复用、回调、缓冲写入及独立游标。每个入口列出参数、结果、状态变化和失败行为。
3. 引擎与语言约定：配置预算、内存、并发、Rust借用/trait/宏/特性开关、C ABI。能用仓颉表达的逐项适配；不能机械复制的机制必须明确替代约定，不能因为结果相同就宣布这一层等价。

速度数值取决于编译器和环境，不能定义为每次执行耗时相同。优化引擎和资源配置的语义仍在工程范围内。测试通过是相应输入的证据，不是全输入数学证明。

## 分阶段推进

| 阶段 | 要交付什么 | 怎样验收 |
|---|---|---|
| 1. 完善现有regex使用层 | 迭代/复制/追加展开/构造便利接口等缺口；逐项处理现有差异 | 每个缺口有原库探针、仓颉对应探针、状态操作序列与回归；旧匹配行为不退化 |
| 2. regex-syntax | 先完成完整公开接口清单，再做AST/HIR数据模型、解析配置、位置错误、打印和访问 | 固定规则集合的结构序列化对照；打印后再解析；配置和错误对照。不得把内部Expr直接改名冒充完整HIR |
| 3. regex-automata基础接口 | 先核对原库实际支持的搜索模式，再提供输入范围、锚定、匹配策略、模式编号、NFA与PikeVM公开操作 | 不同输入范围/起点/模式/状态的差分；多规则位置和捕获。不能猜测原库支持某种匹配策略 |
| 4. 其他引擎与调度 | 按依赖逐步做one-pass、有界回溯、DFA、lazy DFA、反向搜索、预过滤和meta选择 | 每种引擎分别验证接受范围、搜索、错误/预算/缓存；再检验调度结果和资源行为；性能单独测量 |
| 5. 其他产品入口 | regex-lite、C接口；核对regex-cli和regex-test哪些属于可执行交付行为 | 独立功能清单；C调用样例检查ABI、缓冲区与错误；CLI输出和退出码对照 |
| 6. 整体交付 | 固定版本完整范围表、各入口证据、平台和依赖说明 | 干净环境复现；约定平台与配置矩阵；没有未解释的公开能力缺口 |

阶段间允许细分小步，但每步应产出可用实现与独立证据，而不是只有接口空壳。阶段2的完整清单需要覆盖公开类型、方法、枚举、字段、trait及特性，不能把现有170条主要库方法表当作全仓库分母。

## 本轮完成的第一步

新增SetMatches.iter及SetMatchesIter.next/nextBack/clone，字符串和bytes结果共用。它直接扫描私有命中快照，不先收集indices数组；复制游标共享不可变快照，但有独立的前后位置。正反交错不会重复取同一编号，耗尽后两端持续返回None。

新增128项原库/仓颉差分结果：四条规则的16种命中组合，字符串/bytes两种输入，正向/反向/交错/复制四种操作序列。另有原生测试覆盖空集合、重复规则、临时结果生命周期、外部数组修改、非法UTF-8和结束后的复制。

这仅补齐编号迭代的选定行为。Rust Iterator/IntoIterator trait、size_hint、Debug，以及其他迭代器的Clone契约仍需逐项处理。原有数组indices接口继续保留。

## 工程量判断

对齐整个原仓库属于多个子库的移植与兼容工程，明显大于现有主要库的补缺。尤其完整AST/HIR公开模型和多引擎自动机需要独立设计、实现和测试。当前尚无全仓库接口盘点与工时测量，不能可靠地承诺总天数或完成百分比。应先完成阶段1及阶段2接口清单，依据实际差异数量、实现速度和测试成本再估期。

## 下一块优先事项

捕获模板追加写入和SetBuilder数组构造已在2026-10-04补上，两类输入都有原仓库对照。集合大小提示与捕获组迭代器大小/复制契约也已补齐。下一步进入regex-syntax根模块与HIR的具体接口设计和实现；搜索/分割迭代器复制、Debug等主要库剩余约定继续保留在差异表中，不能因此声称阶段1已全部完成。不得把形式差异一律当作缺陷，也不得未经说明就把它们从完整目标里删除。

## 进度数字的使用

“原仓库50%”作为推进目标保留，但目前没有可信的全仓库功能分母。此前约30%的判断只是粗估，不能通过增加方法或测试条数宣称达到50%。先按上述阶段完成可验收功能；全仓库盘点后，按独立能力（而非代码行、重复方法、测试数）列出分母、状态和权重，才能给出可复核的估算。主要库132/170条有样例验证也不能代表全仓库77.6%完成。

2026-10-04已完成regex-syntax公开项目页初查：[范围说明](syntax-scope.md)、[91项类型/函数路径](syntax-public-items.json)。这只是当前配置的项目页清单，尚需展开方法、字段、枚举分支及特性，不能用91作为功能完成率分母。

## HIR第一批实现（2026-10-04）

已提供独立于内部Expr的公开不可变HIR模型，覆盖空、字面量、Unicode/字节字符类、重复、捕获和连接；支持归一化构造、切片解析及节点最短/最长字节长度。详见[实现范围](hir.md)。选择、点号与断言目前显式拒绝，AST、完整配置、打印/访问器仍缺失；不是完整regex-syntax交付。下一批优先补Look和Alternation节点及点号转字符类，再逐步展开属性和配置，不把六类节点解释为语法库75%完成。
