## 如何继续实现

1. 展开根模块和AST/HIR类型的方法、字段、枚举分支，记录原仓库的输入、输出、错误和配置约定。AST保留写法与源码位置，HIR会归一化，两者不能共用一个粗略节点类型冒充。
2. 先交付可检查的HIR节点和属性，配套固定Rust结构序列化探针。最小切片从字面量、连接、选择、重复和捕获开始，随后覆盖字符类与断言；未覆盖节点必须显式拒绝，不能悄悄丢弃。
3. 继续补AST、解析/翻译配置与位置错误，再做打印及访问器。对照既检查结构，也检查打印后再解析的行为；打印成功本身不能证明结构等价。
4. 字面量提取和UTF-8范围工具分别建立对照用例。最后检查trait、可选特性和模块边界，更新完整清单状态。

现有内部解析器能完成搜索，只能说明部分解析语义已用到，不能自动算作公开语法库已经移植。公共模型将作为独立兼容层设计，避免破坏已通过验收的匹配行为。

## 本次提取方式

在仓库根目录进入Rust环境后执行：

```sh
source scripts/env.sh
cargo doc --manifest-path oracle/Cargo.toml -p regex-syntax --no-deps --offline --locked
```

无依赖缓存时去掉`--offline`。文档位于Cargo目标目录的`doc/regex_syntax/`；本机目标目录由环境脚本指定为外部缓存，不纳入交付仓库。提取all.html中的公开项目链接，按路径去重，未将标准库自动trait或通用实现计入以上91项。JSON记录了文档索引哈希，编译器升级可能改变生成文件，因此该哈希不是原仓库源码哈希。
