# 当前交付决定

用户已明确选择：先交付一个整体完整、可验证、可演示、可使用的成果，即使它不是上游所有内容；先学习理解，后续需要时再完善。

因此，**v0.1.0 冻结当前实现范围，优先完成产品入口、演示、学习文档与源码包验收**。详情见 [版本说明](release-0.1.0.md)。不再要求先推进此前估计的 4–6 个扩展阶段才允许交付。

## 本次完成条件

1. 库能被独立仓颉程序依赖，示例可运行并修改。
2. 统一入口能完成构建、演示、查询、快速验收和完整差分验收。
3. 演示有真实输入、独立预期与通过/失败结果。
4. 上手、API、原理和边界说明齐全，初学者无需追溯全部开发记录。
5. 提供源码包和校验文件，并从解压目录验证可复现。
6. 不把范围外能力或尚未验证的平台/性能宣称为完成。

满足这些条件后本轮收尾，留给用户尝试和学习。

## 暂缓的后续方向

大小写与更多标志、剩余 Unicode 属性、Builder、起点搜索、惰性迭代、捕获工作区、bytes、RegexSet、全量 AST/HIR/automata 接口及优化引擎等，继续记录在 [兼容清单](compatibility.md)，暂不自动开工。

此前的“核心增强约 4–6 阶段、完整上游约 12–20+ 阶段”是针对更大范围的粗估，不是本版还需完成的工作，也不是可靠的时间或轮次承诺。今后有实际需求时再重新估算，不用阶段编号代表完成率。
