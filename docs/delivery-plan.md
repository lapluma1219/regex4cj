# 交付边界与剩余工作估算

当前用户目标仍是逐步推进完整转译。以下区分两个验收层次，用于估算和控制投入；核心交付不等于完整仓库转译，不自动替代原目标。比赛评分标准尚未提供，不能据此断言哪一层已足够参赛或获奖。

## 当前判断

现有实现是纯仓颉的标量解析器、有序 Thompson NFA 和常用字符串 API，是受限语义移植。尚未交付上游 regex-syntax / regex-automata 全量公共结构和引擎。已通过的差分测试数量只说明已测行为，不是完成百分比。

近期 Unicode 分步验证降低了错误定位难度，但阶段划分偏细；不应继续按每种属性、每张表单独报一个阶段。后续按完整用户能力合并交付，避免无故重构和追求没有验收指标的性能优化。

## 核心字符串库交付：本轮之后约 4–6 个阶段

这是工程估计，不是时间或调用轮次承诺；复杂度或上游测试暴露的问题会改变估计。

| 合并工作包 | 范围 | 退出条件 |
|---|---|---|
| 语法与 Unicode 语义，约 1–2 阶段 | 大小写折叠 i、x/R 等标志、方向性词边界、Unicode 组名、剩余重复语法；列明 u/ASCII 模式与剩余属性边界 | 支持项有 Rust 对照；无法支持的项明确记录并报错；不能把 Unicode 属性表齐全当作大小写语义齐全 |
| 顶层字符串 API，约 1–2 阶段 | RegexBuilder、带起点的搜索、惰性匹配/捕获/分割迭代、元数据与捕获辅助接口；逐项登记缺失接口 | 有源代码定位的接口映射表；正常、空匹配、UTF-8 起点、错误情形与上游对照 |
| 集中兼容验收，约 1 阶段 | 导入适用上游测试语料、固定种子差分与失败回归；检查超长输入和资源限制 | 所有适用语料通过，跳过项有明确理由；剩余差异可枚举；不以新增随机用例数量作为结束条件 |
| 交付与性能基线，约 1 阶段 | 干净环境复现、目标平台构建、库消费示例、演示、来源许可、性能和内存基线 | 新环境可按文档构建/验收；演示步骤稳定；报告实际平台与性能边界；没有已知的约定范围内阻断缺陷 |

这一层允许明确不含任意字节 API、RegexSet、底层全部 AST/HIR/automata API 和多种优化引擎。若评分要求它们，必须纳入验收范围，不能称这一层为满足比赛全部要求。

## 整个上游仓库完整对齐：粗估 12–20 个以上阶段

此估计置信度低：全量公开 API 清单、feature 组合、平台范围、性能目标尚未冻结，也未把各工作包细分估时。不能承诺再固定几轮就全部完成。

除上述工作，还至少包括：任意字节匹配与 Unicode 开关、RegexSet、regex-syntax 的完整 AST/HIR 与诊断 API、regex-automata 的配置和多引擎公共 API、DFA/lazy DFA/预过滤/缓存、相关仓库包与工具，以及更全面的平台和性能对照。部分工作会改变当前标量引擎架构，不能视作再补几张表。

## 顶层 API 抽查证据

对固定上游 `src/regex/string.rs` 的公开方法做了源码抽查，主要缺口如下。这不是完整静态分析清单；trait 实现、Builder、bytes、Set 及其他包需要单独核对。

| 上游行为 | 当前状态 |
|---|---|
| new、is_match、find | 有对应核心接口 |
| find_iter、captures_iter、split、splitn | 有立即收集结果的等效常用操作，尚非惰性迭代 API |
| replace / replace_all / replacen，Captures::expand | 已有常用对应操作与模板/回调支持 |
| shortest_match / shortest_match_at | 尚缺；不能用普通 find 的结束位置冒充 |
| is_match_at / find_at / captures_at | 尚缺公开起点接口，需处理起点与上下文断言 |
| captures_read / captures_read_at / capture_locations | 尚缺可复用捕获工作区 |
| as_str / static_captures_len / Captures::extract | 尚需接口映射与实现核对 |
| capture_names / captures_len / Captures::get / name | 已有对应能力 |

## 控制投入的规则

- 每一轮交付可使用的功能或修复真实缺陷，不为重构而重构。
- 新语义先做针对性对照，代码稳定后运行一次完整验收；只有新的修改、失败或证据才重复验收。
- 不并发重建正在被其他测试使用的二进制，避免无意义的测试中断。
- 数据表由固定上游自动生成，不逐表人工转写；保留必要来源与许可证。
- 首先保证结果、偏移、捕获和错误边界；性能优化以基线和明确目标为触发条件。
- 在核心交付条件满足时报告可交付状态和剩余范围，完整转译是否继续按比赛要求与用户目标决定。
