# 第十步：Unicode 词边界

支持 `\b` 和 `\B` 零宽断言，复用 Unicode 16.0.0 的 `\w` 集合，不新增数据版本或外部依赖。

在当前位置，左侧和右侧各取一个 Unicode 标量，文本之外视为非单词字符：

- 两侧的单词字符属性不同，匹配 `\b`。
- 两侧属性相同，匹配 `\B`。

因此空文本中 `\b` 不匹配，`\B` 匹配；中文之间通常没有词边界，组合标记和 Join_Control 也遵循 `\w` 定义。这是字符属性边界，不是自然语言分词、UAX #29 单词切分或字素簇边界。

## 实现

对应固定上游 commit `72d650cb0a880a01ab6dc2137c0888e8f89740f7` 的 `regex-automata/src/util/look.rs`：`is_word_unicode`、`is_word_unicode_negate`。

解析器生成零宽表达式，编译为词边界 NFA 状态；有序闭包检查原文位置两侧的字符属性。只在含存活边界状态的 Regex 中加载一次单词字符集合，普通表达式不承担这项额外分配。重复中的零宽正规化沿用现有规则。

仓颉当前引擎扫描有效字符串的标量位置，因此不会在 UTF-8 多字节编码内部产生匹配。上游 bytes API 对无效 UTF-8 的行为不在本阶段范围内。后续搜索仍读取原文前后字符，不把每次搜索起点视为文本开头。

`[\b]`、`[\B]` 明确报错；其中 `\b` 不表示退格，退格可以写作 `\x08`。方向性边界 `\b{start}`、`\b{end}`、半边界及禁用 Unicode 的 ASCII 模式尚未支持。

## 使用

在 bash 中加载环境后：

```sh
source scripts/env.sh
cli/target/release/bin/main find '\bcat\b' 'cat cats cat'
cli/target/release/bin/main find '\b\w+\b' '中文🙂abc'
```

第一条只得到两个独立的 `cat`，跳过 `cats`；第二条得到 `中文 [0,6)` 和 `abc [10,13)`。
